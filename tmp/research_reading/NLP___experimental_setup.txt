End-to-End Data & Experiment Pipeline
for the SIC Project (multi-hop Semantic Induction Circuits)
Working plan — based on Ren et al. 2024 and the project proposal
September 2026
This document lists everything we need — data, models, tooling, and processing steps — in the
order we should build it, adapted from the experimental setup of Ren et al. 2024 (Identifying
Semantic Induction Heads) to our research question (distributed Semantic Induction Circuits for
multi-hop relations).
1 Pipeline overview (build in this order)
1. Choose model suite + checkpoints; verify TransformerLens support.
2. Generate synthetic multi-hop ICL datasets (gold relations known by construction).
3. Tokenize and anchor: map every entity to its token indices; fix a multi-token convention.
4. Run with activation caching; compute per-head Relation Index (RI), reproducing Ren et al.
on 1-hop as a sanity check.
5. Generalize RI to circuits; run activation / path patching; measure faithfulness of the sparse
subgraph.
6. Sweep across training checkpoints; separate format-compliance failures from pattern-discovery
failures.
2 Models and checkpoints
Ren et al. used InternLM2-1.8B (24 layers×16 heads) for the head analysis, and trained their own
1.1B model on SlimPajama with checkpoints every 200 steps for the ICL-emergence experiments.
We donottrain: we use public checkpoint suites.
•Pythia(EleutherAI): 154 checkpoints per model size, fully public training data order. Repo:
https://github.com/EleutherAI/pythia; models on HF, e.g. pythia-160m . . . pythia-1b
(checkpoints via therevisionargument, e.g.revision="step3000").
•OLMo(AI2):https://github.com/allenai/OLMo; checkpoints on HF.
•LMEntsuite (named in our proposal): locate via arXiv / HF search and confirm checkpoint
availability before committing to it.
•Tooling: TransformerLens — check the supported-models list; Pythia and OLMo are sup-
ported. All caching and patching goes throughrun with cacheand hook points.

3 Datasets
3.1 What Ren et al. used (our 1-hop reference)
•AGENDA (Koncel-Kedziorski et al. 2019): 1,000 test samples; each = a scientific abstract +
a knowledge graph of entities and typed relations,anchored in the text. Used for knowledge-
graph relations.
•Syntactic dependencies: sentences split from the same paragraphs, parsed with spaCy. Note:
these gold labels are themselves model output (parser noise) — a caveat they inherit and we
avoid.
•ICL-levels tasks: few-shot classification prompts (their Table 1); format compliance = the
forced single generated token has the righttype(e.g. a digit), pattern discovery = the label is
correct; class-balanced shots.
3.2 What we build (multi-hop, synthetic)
Generated from templates so that gold relations are known by construction — no parser, no anno-
tation noise.
•Template sources: CLUTRR (compositional kinship reasoning; built for exactly this) and
bAbI tasks. Per the proposal, replace all real nouns with fictitious entities so the model cannot
answer from parametric memory.
•Each sample must carry: the prompt text; the list of gold triples (head,relation,tail);
for multi-hop, the chain (e.g.A⊂B,B⊂C⇒A⊂C) with thebridge entitymarked;
character-level spans of every entity occurrence.
•Matched difficulty tiers: 1-hop (reproduces Ren et al.’s setting), 2-hop, optionally 3-hop
— same entities, same format, so hop count is the only manipulated variable.
•Controls to generate alongside(needed later for patching and for RI baselines): corrupted
prompts (bridge entity replaced — breaks the chain while preserving format); shuffled-relation
prompts; and Ren et al.’s trick of afake tailbaseline (they re-computed RI with the tail forced
to an arbitrary token — e.g. the 10th token — as a null distribution).
•Anti-confound rule: the query pair must never appear verbatim as an in-context example
— otherwise a plain (non-semantic) induction head solves the task by literal copying and
inflates our results.
•Class balance: when shots≥number of answer classes, include at least one example per
class (Ren et al.’s protocol), so that format accuracy is well-defined.
4 Tokenization and anchoring
The single most error-prone step. Annotations live on words/entities; the model lives on sub-word
tokens.

1. Tokenize each prompt with thesuite’s own tokenizer; build a map from every entity occurrence
(character span) to a contiguous range of token indices.
2. Fix a convention for multi-token entities (fictitious names will split into several tokens). Ren
et al. operate at the token level; for spans, the common convention is to use thelasttoken of

robustness to it.
3. Store, per sample:(prompt, token ids,{entity→[token idx range]}, gold triples,
chain structure)— e.g. one JSONL line per sample.

Our extension (core novelty): generalize RI from a single head to acircuit: for 2-hop, no single
head needs to linkAtoC; instead headh 1 may resolveA→Band write it to the residual stream,
andh 2 read it and resolve→C(composition). The circuit-level RI must therefore score (i) per-
edge behavior and (ii) the causal link between the heads — which is what path patching measures
(below), so the metric and the intervention should be designed together.
5.2 ICL levels (for the checkpoint sweep)
Follow Ren et al.§4:loss reduction— interval-averaged version of Olsson et al.’s score (mean
loss over tokensj . . . i+jminus mean over 0. . . i);format compliance— forced single-token
generation, check the token’s type;pattern discovery— label accuracy. Report all three per
checkpoint so that “no SIC yet” is never confused with “model cannot even comply with the format
yet”.
6 Causal experiments
To learn/implement (in this order):
1.Activation patching(node-level): replace a head’s/MLP’s activation with its value from the
corrupted prompt; measure the drop in the correct-answer probability. Primer: Heimersheim
& Nanda 2024, “How to use and interpret activation patching”; origins: ROME / causal
tracing.
2.Path patching(edge-level): patch only along the path from componentXto componentY
— this is what substantiates “h 1 feedsh 2”, i.e. the circuit claim. Canonical use: Wang et al.
2022 (IOI) — near-mandatory reading; our faithfulness protocol is modeled on it.

3.Faithfulness(proposal§3): run the model with only the identified sparse subgraph active
(everything else mean-ablated or frozen); compare correct-answer probability to the full model.
Define the recovery thresholdin advance. Rigor ceiling for this kind of claim: causal scrubbing
(skim).
7 Sanity checks and baselines
•Reproduce Ren et al. qualitatively on 1-hop relations before any 2-hop work (small scale: a
few relations, a few hundred samples).
•Fake-tail / random-tail RI baseline (their trick) as the null distribution for every RI heatmap.
•Plain induction-head baseline: measure prefix-matching and copying scores (Olsson et al.) on
the same heads, to show SIC heads are not just literal-copy heads — and vice versa.
•Random / earliest-checkpoint model as a floor for every metric.
•Verify the anti-confound rule held (no verbatim query repetition) by scanning generated
prompts.
8 Storage and compute notes
∼100–1,000 prompts×dozens of checkpoints: cache per-headscores, not raw attention (L H n 2
floats per prompt adds up fast); batch prompts per checkpoint load (loading a checkpoint dominates
wall-time); models≤1B fit the studentkillable Slurm partition per the proposal.
